# theadoc

Collaborative Markdown documents with AI-generated interactive widgets. Documents sync through Automerge, remain available offline in IndexedDB, and are shared through unguessable edit links.

## Run

Requirements: Docker Engine with the Compose plugin, and `just`.

Local development and production run the same `compose.yaml` (app plus Caddy). Only `.env` differs:

```sh
cp .env.example .env
# Add a capped OPENROUTER_API_KEY to .env.
just up      # build and (re)start in the background
just logs    # follow logs
just down    # stop and remove containers; data/ is kept
just check   # lint and test inside the Docker build
```

Locally, the defaults in `.env.example` serve the app at http://localhost and sync at `ws://sync.localhost`, both through Caddy on port 80. Persistent data is written to `./data`.

## OpenRouter budget

Use a dedicated inference key rather than a management key. Create it in OpenRouter with a fixed USD limit and no reset; `$10` is the suggested demo ceiling. The application additionally allows two concurrent generations and queues ten.

The default model is `openai/gpt-5.6-terra`. Override it with `OPENROUTER_MODEL`; it must support tool calling.

## Widget generation

Widgets are generated by an agent loop (Vercel AI SDK `ToolLoopAgent` over OpenRouter). The agent edits a small TypeScript workspace (`body.html`, `style.css`, `main.ts`), adds npm packages, and builds with esbuild until the bundle compiles. Progress streams to the browser as newline-delimited JSON.

- Packages are resolved to exact versions from the npm registry and installed with `--ignore-scripts`. Packages below `MIN_WEEKLY_DOWNLOADS` (default 500), deprecated or platform-specific packages are rejected.
- Each generation is capped at `MAX_AGENT_STEPS` (default 24) model steps and `MAX_AGENT_TOKENS` (default 400000) tokens, plus a five-minute timeout.
- The container needs outbound HTTPS to `registry.npmjs.org` and `api.npmjs.org`.

### Measuring and choosing a model

Every agent step logs one JSON line (`"event":"generation_step"`: tools called, duration, input/cached/output/reasoning tokens), and every attempt logs a summary (`"event":"generation_run"`). Read them with `just logs`; dollar costs per request are in the OpenRouter activity dashboard.

What to look for: if `cached` stays near zero on later steps, prompt caching is not working; if `reasoning` dominates `output`, the model thinks more than it writes; if runs take many steps, the time goes to round trips rather than to any single call.

The whole loop runs on one model. To try a cheaper or faster one, set `OPENROUTER_MODEL` in `.env`, run `just up`, and generate the same handful of specs (a chart, a map, a form-like interaction, a 3D scene) with each candidate, comparing quality, run time and cost. Candidates to try first, all with tool calling (prices per million input/output tokens from OpenRouter's model list on 2026-10-26; the default `openai/gpt-5.6-terra` is $2 / $12):

```sh
OPENROUTER_MODEL=anthropic/claude-haiku-5.5   # $0.10 / $0.50
OPENROUTER_MODEL=moonshotai/kimi-k2.7-code    # $0.67 / $3.35
OPENROUTER_MODEL=x-ai/grok-4.3                # $1.25 / $2.50
```

Anthropic routes on OpenRouter need explicit cache markers, which the generator does not set, so expect `cached` to stay at zero with Haiku. List current IDs and prices with `curl -s https://openrouter.ai/api/v1/models`. If a cheaper model only falls short on hard specs, the next step is splitting per step (cheap model first, current default on the retry) rather than switching back entirely.

## Ubuntu VPS deployment

The production target is Ubuntu 24.04 with Docker Engine, the Compose plugin, two DNS names, and provider-managed daily snapshots.

### 1. Prepare the host

Create a non-root deployment user and install Docker from Docker's official apt repository. Add the user to the `docker` group. Enable the firewall while preserving SSH:

```sh
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw enable
```

Point DNS A records for both names at the VPS:

- `theadoc.example.com`
- `sync.theadoc.example.com`

Add AAAA records only if IPv6 is configured on the VPS.

### 2. Configure

Clone the repository, enter `web-demo`, and create the production environment:

```sh
cp .env.example .env
chmod 600 .env
mkdir -p data
```

Switch `APP_DOMAIN`, `SYNC_DOMAIN` and `VITE_SYNC_URL` to the commented production values, and set `ACME_EMAIL` and the capped `OPENROUTER_API_KEY`. The application is intentionally public: possession of a document URL grants edit access, and no document index is exposed.

The container runs as UID 1000. On a new host, give it ownership of the data directory:

```sh
sudo chown -R 1000:1000 data
```

### 3. Start and verify

```sh
just up
docker compose ps
just logs
curl -fsS "https://$APP_DOMAIN/api/health"
curl -fsS "https://$SYNC_DOMAIN/"
```

Caddy obtains and renews TLS certificates. Only Caddy publishes host ports; application and sync ports remain inside the Compose network.

### Updates and rollback

Take a provider snapshot before an upgrade, then:

```sh
git pull --ff-only
just up
```

To roll back, check out the previous known-good commit and run `just up` again. Do not remove `data/` or run `docker compose down -v`.

### Backups

Enable daily snapshots in the VPS provider dashboard. For a manual portable data backup, briefly stop the writer and archive the bind mount:

```sh
docker compose stop theadoc
tar -czf "theadoc-data-$(date +%Y%m%d-%H%M%S).tar.gz" data
docker compose start theadoc
```

Copy the archive off the VPS. Restore by stopping theadoc, replacing `data/` from an archive, restoring ownership to UID 1000, and starting the service again.

## Storage

- Automerge repository: `/data/automerge`
- Immutable generated artifacts: `/data/widgets`
- Immutable, content-addressed widget bundles: `/data/bundles`
- Installed widget dependencies and npm cache: `/data/packages`, `/data/npm-cache` (safe to delete; reinstalled on demand)
- Browser-local document cache: IndexedDB
- Browser-local recent list: localStorage

Generated code runs in a sandboxed iframe without same-origin access. Widget artifacts and their bundles are immutable JSON files and are included alongside Markdown in portable `.theadoc.zip` exports, so exported widgets render without network access.
